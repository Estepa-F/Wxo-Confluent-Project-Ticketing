# App: `support_portal`

One FastAPI application, packaged as one Docker image, that plays every non-AI role of the demo: the customer portal, the presenter dashboard, the support advisor's console, a synthetic ticket generator, the MCP server used by the Confluent triage agent, and the client of the watsonx Orchestrate escalation agent.

Deployed on AWS ECS Express behind CloudFront by `deploy.py --stage app` (see [`terraform/app-hosting`](../terraform/app-hosting)).

## Run locally

```bash
cd app
uv run python -m support_portal --disable-generator
```

Without Confluent credentials, Kafka calls are silent no-ops. Pages:

| URL | Who | What |
|---|---|---|
| `/` | Customer | New ticket form |
| `/tickets`, `/tickets/{id}` | Customer | Ticket list and timeline (live over WebSocket) |
| `/dashboard` | Presenter | Live Triage Stream, volumes and forecast, sentiment, incident / burst / generator controls, copilot bubble |
| `/support-admin` | Support advisor | Escalated queue, escalation agent's draft, human reply |
| `/status` | Anyone | Health check |

Presenter endpoints under `/admin/*` require the `X-Admin-Token` header.

## Code layout

| Folder | Role |
|---|---|
| [`support_portal/tickets/`](support_portal/tickets) | Ticket lifecycle: models, in-memory store, HTTP and WebSocket routes, sample tickets |
| [`support_portal/messaging/`](support_portal/messaging) | Kafka producer and consumers, wire schemas (JSON Schema, Avro for `tickets.metrics`) |
| [`support_portal/mcp/`](support_portal/mcp) | MCP server for the triage agent: `search_known_issues`, `get_account_context` (HTTP Basic auth) |
| [`support_portal/orchestrate/`](support_portal/orchestrate) | Calls the Orchestrate escalation agent for escalated tickets, parses its draft, publishes it to `tickets.escalation-drafts` |
| [`support_portal/incidents/`](support_portal/incidents) | Known-issues knowledge base and the service status the presenter flips |
| [`support_portal/generator/`](support_portal/generator) | Synthetic baseline traffic and on-cue bursts |
| [`support_portal/accounts/`](support_portal/accounts) | Pre-seeded pool of customer accounts (tiers bronze, silver, gold) |
| [`support_portal/dashboard/`](support_portal/dashboard), [`admin/`](support_portal/admin) | Dashboard state and presenter controls |
| [`support_portal/static/`](support_portal/static) | HTML/CSS/JS front-ends (no framework); `copilot-embed.js` loads the Orchestrate chat bubble from `copilot-config.json`, generated by `setup_demo.sh` step 8 |

## Configuration

`app/.env` is written by `deploy.py --stage base`; see [`.env.example`](.env.example). Main settings:

| Variable | Default | Description |
|---|---|---|
| `ACCOUNT_POOL_SIZE` | `250` | Number of pre-seeded customer accounts |
| `MATCH_THRESHOLD` | `50` | Fuzzy-match score for a known issue (tune during rehearsal) |
| `ADMIN_TOKEN` | — | Token for the presenter endpoints |
| `ENABLE_GENERATOR` / `GENERATOR_RATE` | `true` / `0.1` | Synthetic traffic, tickets per second |
| `MCP_ALLOWED_HOSTS` | `localhost:*,…` | Hosts allowed by the MCP SDK's DNS-rebinding protection |
| `CC_BOOTSTRAP_SERVERS`, `CC_*` | — | Confluent Cloud Kafka and Schema Registry (omit to run without Kafka) |
| `MCP_USERNAME` / `MCP_PASSWORD` | — | Basic auth for the MCP endpoint (set by Terraform) |

Detailed specs: [`docs/specs/`](../docs/specs).
